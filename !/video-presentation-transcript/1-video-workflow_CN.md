# 视频 1：从 Vibe Coding 到代理工程——使用 Claude Code 构建工作流

**总时长：约 5 分钟**

---

## 引言——问题所在（0:00 – 0:45）

- "如果你刚开始使用 Claude Code，很可能还在用 vibe coding 的方式——输入提示词、获取结果、不断重复。这确实能工作，但你只用了 Claude Code 能力的冰山一角。"
- "这个仓库是一个精心整理的最佳实践合集，带你从 vibe coding 迈向代理工程——让 Claude 不再只是被动响应，而是为你运行自动化的流程。"
- "在第一个视频中，我将讲解基础知识：**命令、代理和技能**——以及它们如何串联成可重复执行的工作流。"

---

## 第一部分——即席方式（0:45 – 2:00）

**演示：Vibe coding 方法**

- 打开一个全新的 Claude Code 终端
- 输入：*"迪拜的天气怎么样？把它写入一个输出文件，并为它创建一个 SVG 卡片。"*
- 展示结果——它能工作，但指出问题：
  - SVG 设计每次都不同（随机颜色、布局、字体）
  - 你需要坐着看它工作
  - 如果明天再运行一次，你会得到一张完全不同的卡片
- **打开第二个终端，再次运行同样的提示词**
  - 并排展示 SVG——它们看起来不一样
- "这就是 vibe coding 的问题。它能工作一次，但不可重复。它不是一个你能够信赖的工作流。"

---

## 第二部分——工作流方式（2:00 – 3:15）

**演示：`/weather-orchestrator` 命令**

- "现在让我展示同样的任务，但以工作流的方式来运行。"
- 输入：`/weather-orchestrator`
- 逐一讲解屏幕上发生的事情：
  1. 它**询问你**选择摄氏度还是华氏度（结构化的用户交互）
  2. 它**生成一个 weather-agent** 来获取温度（你会在终端看到绿色的代理）
  3. 它**调用一个技能**来创建 SVG 卡片
  4. 输出：`orchestration-workflow/weather.svg` + `orchestration-workflow/output.md`
- "再次运行它——相同的 SVG 布局，相同的文件结构，同样干净的结果。每次都是如此。"
- "你可以启动它然后走开。它会自主运行。"

---

## 第三部分——工作原理：命令 → 代理 → 技能（3:15 – 4:30）

**讲解三个构建模块**

### 命令（`.claude/commands/`）

- "命令是入口点——就像一个脚本。它是一个 markdown 文件，告诉 Claude *要遵循哪些步骤*。"
- "我们的 `weather-orchestrator` 就是指挥者。它向用户提问，调用一个代理，然后调用一个技能。"
- 命令存放在 `.claude/commands/` 中，以 `/slash-commands` 形式显示

### 代理（`.claude/agents/`）

- "代理是专门的工作者。我们的 `weather-agent` 只有一个任务：获取温度。"
- "它有一个**预加载的技能**叫做 `weather-fetcher`——该技能在启动时被注入到代理的上下文中，因此代理确切知道要调用哪个 API 以及如何解析响应。"
- 代理拥有自己的工具、模型和权限。它们是隔离的工作者。

### 技能（`.claude/skills/`）

- "技能是一组可复用的指令。可以把它们想象成菜谱。"
- "这里我们有两种技能模式："
  - **代理技能**（预加载）：`weather-fetcher` 内置于代理中——它是领域知识
  - **调用式技能**：`weather-svg-creator` 通过 Skill 工具独立调用——它创建 SVG 卡片
- 技能可以是背景知识，也可以是独立操作

### 流程图（可选，可在屏幕上展示）

```
/weather-orchestrator（命令）
    → AskUser：摄氏度还是华氏度？
    → weather-agent（代理 + weather-fetcher 技能）
    → weather-svg-creator（技能）
    → 输出：weather.svg + output.md
```

---

## 第四部分——为何重要 / 总结（4:30 – 5:00）

- "vibe coding 和代理工程之间的区别在于**结构**。"
  - Vibe coding：你输入，你期望，你得到某个结果。
  - 代理工程：你定义一次工作流，它每次都按相同方式运行。
- "命令、代理和技能是三个构建模块。一旦你理解了这些，你就可以构建任何工作流。"
- "这个仓库还有更多模式——钩子、多代理团队、CLAUDE.md 配置——我们会在后续视频中讲解。"
- "仓库链接在描述中。点星标、克隆仓库，然后开始构建你自己的工作流。"

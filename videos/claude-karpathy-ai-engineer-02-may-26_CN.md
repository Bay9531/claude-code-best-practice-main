## 对话记录

### 介绍

我们非常兴奋地迎来我们的第一位特邀嘉宾。他帮助构建了现代 AI，然后解释了现代 AI，然后偶尔给现代 AI 重新命名。他实际上就在这间办公室里共同创立了 OpenAI。曾经是让特斯拉的 Autopilot 运行起来的人，他有一种罕见的天赋，能让最复杂的技术变革既显得可及又似乎是必然的。你们都因为他在去年创造了"vibe coding"这个术语而认识他，但在过去的几个月里，他说了一些更加惊人的话。他说他作为一名程序员，从未感到如此落后。这就是我们今天开始的地方。谢谢你加入我们，Andrej。

是的。你好。很高兴来到这里，为我们的活动开场。

### "从未感到如此落后"

好的。就在几个月前，你说过作为一名程序员，你从未感到如此落后。这话从你嘴里说出来实在令人惊讶。你能帮我们解读一下吗？这种感觉是令人振奋还是不安？

是的，肯定是两者兼有。首先，和你们很多人一样，我一直在使用像 Claude Code 这样的代理工具以及类似的东西，大概在过去一年里，它刚出来的时候，它对代码片段很擅长，但有时会搞砸，你需要编辑它们，它算是有点帮助。然后我认为 12 月是一个明确的转折点——我当时在休假，所以有更多时间。我想很多人也类似——我开始注意到，有了最新的模型，代码片断直接就能用得很好，然后我不断要求更多，它还是直接就能用，然后我想不起来上次纠正它是什么时候了。然后我越来越信任这个系统，然后我就开始 vibe coding 了。

所以这是一个非常明显的转变。我认为很多人实际上——我试图在 Twitter（或 X）上强调这一点——因为我认为很多人去年体验到 AI 是作为类似 ChatGPT 的东西。但你真的需要重新审视，你需要从 12 月开始重新审视，因为事情已经发生了根本性的变化——尤其是在这个真正开始奏效的代理式连贯工作流上。所以我会说，正是这个领悟让我彻底投入了这个兔子洞，开始了无穷无尽的副项目。我的副项目文件夹里装满了各种随机的东西，我一直在 vibe coding。所以这大概发生在 12 月，我一直在关注其影响。

### 软件 3.0：新的计算范式

你谈到了很多关于将 LLM 视为一种新计算机的想法。它不仅仅是更好的软件，它是一个全新的计算范式。软件 1.0 是显式规则，软件 2.0 是学习到的权重，软件 3.0 就是这个。如果这真的成立，一个团队在真正相信这一点的那一天，会以什么不同的方式构建呢？

对的。所以软件 1.0，我在写代码；软件 2.0，我实际上是通过创建数据集和训练神经网络来编程。所以编程就像是安排数据集以及一些目标和神经网络架构。然后发生的是，如果你把其中一个 GPT 模型或 LLM 在一个足够大的任务集上训练——隐式地，因为通过在互联网上训练，你必须多任务处理数据集中所有的东西——这些实际上在某种意义上变成了一台可编程的计算机。

所以软件 3.0 是关于你的编程现在变成了提示词，上下文窗口中的内容是你对这个"解释器"——即 LLM，它正在解释你的上下文并在数字信息空间中执行计算——施加的杠杆。

我认为有几个例子真正让我明白了这一点。例如，当 OpenClaw 出来的时候，你想安装 OpenClaw，你通常会期望这是一个 bash 脚本，一个 shell 脚本。所以运行 shell 脚本来安装 OpenClaw。但问题是，为了支持很多不同的平台和很多不同类型的计算机来运行 OpenClaw，这些 shell 脚本通常会膨胀得极其复杂。但问题是，你仍然被困在想写代码的软件 1.0 的思维中。实际上 OpenClaw 的安装是一堆你要复制粘贴给你的代理的文本。所以基本上它是一个小技能——"复制粘贴这个，给你的代理，它就会安装 OpenClaw"。而这之所以强大得多，是因为你现在在软件 3.0 范式中工作，不需要精确地阐明设置的所有个别细节。代理拥有自己的智能，它打包起来，然后遵循指令，查看你的环境、你的计算机，并执行智能操作来让事情工作，并在过程中进行调试。它强大得多。所以这是一种非常不同的思考方式——什么是你要复制粘贴给你的代理的文本？这就是编程范式。

### MenuGen 和"不应该存在的应用"

现在我想到了另一个更极端的例子，那就是我在构建 MenuGen 的时候。MenuGen 是这样的想法：你去一家餐厅，他们给你一份菜单。通常没有图片。所以我完全不知道这些东西是什么——通常 30% 的东西我完全不知道它们是什么，50% 不知道。所以我想拍一张餐厅菜单的照片，并获取这些菜品的通用图片。

我用 vibe coding 构建了这个应用，它可以让你上传照片，然后它会做所有这些事情，运行在 Vercel 上，它基本上重新渲染菜单，给你列出所有菜品，并用图像生成器 OCR 识别所有不同的标题，用图像生成器获取它们的图片，然后展示给你。

然后我看到了软件 3.0 版本——这让我震惊——就是直接把你的照片给 Gemini 并说"用 Nanobanana 把东西叠加到菜单上"。Nanobanana 基本上返回了一张图片，正是我拍的那张菜单照片，但它实际上在像素中渲染了菜单中的不同菜品。这让我震惊，因为我所有的 MenuGen 都是多余的。它是在旧的范式中工作。那个应用不应该存在。

软件 3.0 范式中更加原始。你的神经网络在做越来越多的工作，你的提示词或上下文只是图像，输出是图像，不需要中间有任何应用。所以人们需要重新构建思维框架——不要仅仅在现有范式内工作，把它看作是对现有事物的加速。新的可能性现在出现了。

回到你关于编程的问题，我认为这也是在旧思维模式下工作的一个例子——因为这不仅仅是关于编程和编程变得更快。这是更普遍的信息处理现在可以被自动化了。所以它甚至不仅仅是关于代码。之前的代码是处理结构化数据的，对吧？你为结构化数据写代码。但例如，我的 LLM 知识库项目——基本上你让 LLM 为你的组织或为你个人创建 Wiki——这甚至不是一个程序。这在以前是不可能存在的，因为没有代码能基于一堆事实创建一个知识库。但现在你可以直接拿这些文档，以不同的方式重新编译它们，重新排序，创造一些新的有趣的东西，作为数据的重新构建。这些都是以前不可能的新事物。所以我认为这是我不断想回到的一点——不仅仅是关于我们能以更快的速度做什么，而是有全新的机会，做以前不可能的事情，我几乎认为这更令人兴奋。

### 展望 2026 及未来

我喜欢 MenuGen 的演进和你提出的二分法。如果你进一步推演，2026 年的对应物是什么——就像 90 年代建网站、2010 年代建移动应用、上一个云时代建 SaaS？什么事后会看起来完全显而易见，但今天大部分还没有被构建？

继续拿菜单的例子——很多这些代码不应该存在，只是神经网络在做大部分工作。我确实认为这个推演看起来非常奇怪，因为你基本上可以想象在某种意义上完全神经化的计算机。你输入原始视频——想象一个设备，接收原始视频或音频到基本上是一个神经网络中——并使用扩散来渲染一个在这一刻独特的 UI。

我有点觉得在计算的早期，人们实际上有点困惑——计算机是会像计算器，还是计算机看起来像神经网络。在 50 年代和 60 年代，哪种方向会胜出并不是很明显。当然我们走了计算器的路，最终构建了经典计算，而神经网络目前虚拟化运行在现有计算机上。但我认为很多事情会翻转，神经网络会成为主进程，CPU 成为协处理器。所以我们看到智能计算的图表——神经网络的 FLOPs 将占据主导地位，成为 FLOPs 的主要支出。所以你可以想象一些非常奇怪和陌生的东西——神经网络在做大部分繁重工作。它们使用工具调用作为这个历史的附属物来完成某些确定性任务。但真正掌控全局的是这些神经网络。所以你可以想象一个非常陌生的推演，但我想我们可能会一步一步地到达那里。

### 可验证性与锯齿状智能

我想谈谈可验证性这个概念——AI 会更快速、更容易地自动化那些输出可以被验证的领域。如果这个框架是正确的，那么哪些工作将会比人们意识到的更快地被自动化，哪些我们以为是安全的职业实际上具有很高的可验证性？

所以我花了一些时间写了关于可验证性的文章。基本上，传统计算机可以轻易自动化那些你可以用代码指定的东西，而最新一轮的 LLM 可以轻易自动化那些你可以验证的东西——在某种意义上——因为工作的方式是，当前沿实验室训练这些 LLM 时，它们是巨大的强化学习环境。所以它们被给予验证奖励，然后由于这些模型的训练方式，它们最终基本上不断进步，创造出这些锯齿状的实体，它们在可验证的领域（如数学和代码）中能力达到顶峰，而在那些不在这个空间的事物上则有些粗糙。

所以我写关于可验证性的原因是，我试图理解为什么这些东西如此锯齿状。其中一些与实验室训练模型的方式有关，但我认为还有一些与实验室的关注点以及他们碰巧放入数据分布的内容有关。因为有些事情在经济上显著更有价值，最终创造了更多的环境，因为实验室想在这些环境中工作。所以我认为代码是一个很好的例子。可能有很多他们可以考虑的可验证环境，但它们没有进入混合，因为它们拥有这些能力并不那么有用。

一个大谜团——好一阵子最喜欢的例子是"'strawberry'中有多少个字母"，模型会著名地弄错，这是锯齿状的一个例子。模型现在修补了这个，我想。但新的问题是："我想去一个洗车场洗车，距离 50 米。我应该开车还是走路？"最先进的模型今天会告诉你走路，因为它太近了。最先进的 Opus 4.7 怎么可能同时重构一个 10 万行的代码库，或者发现零日漏洞，却告诉我要走路去洗车？这太疯狂了。

无论这些模型保持锯齿状的程度如何，这表明：第一，可能有些东西不太对劲；或者第二，你需要在一定程度上参与其中，你需要把它们当作工具，并且确实需要关注它们在做什么。所以我的所有文章，长话短说，关于可验证性——就是试图理解为什么这些东西是锯齿状的。是否存在某种模式？我认为这是某种"可验证性 + 实验室在乎"的组合。

也许还有一个有启发性的轶事：从 GPT-3.5 到 GPT-4，人们注意到国际象棋改进很多，很多人认为"哦，这只是能力的进步"——但实际上，更多是因为大量国际象棋数据进入了预训练集，仅仅因为它在数据分布中，模型改进得比它默认情况下要多得多。所以 OpenAI 的某个人决定添加这些数据，然后你突然就有了一个大幅提升的能力。

这就是为什么我要强调这个维度：因为我们有点受制于实验室在做什么，受制于他们碰巧放入混合中的东西。你必须实际探索他们给你的这个东西——它没有说明书。它在某些环境中有效，但可能在其他环境中无效。如果你处于构成 RL 一部分的回路中，你就飞起来了。如果你处于数据分布之外的回路中，你就会挣扎，你必须弄清楚你的应用处于哪些回路中。如果你不在这些回路中，那么你真的需要考虑微调和自己做一些工作，因为 LLM 不太可能开箱即用。

### 给创始人的建议

如果你今天是一个创始人，正在考虑创办一家公司，你正在尝试解决一个你认为可行的问题——一个可验证的领域——但你环顾四周，你想，"哦天哪，实验室已经开始在最明显的领域——数学、代码等——达到逃逸速度。"你会给在座的创始人什么建议？

我确实认为在当前范式下，可验证性使得某件事是可行的，因为你可以在上面投入大量的 RL。所以一种看法是，即使实验室不直接关注它，这仍然是真实的。所以如果你处于一个可验证的环境中，你可以创建这些 RL 环境或示例，那么这实际上让你有可能做自己的微调，并从中受益。这是根本上可行的技术。如果你有大量多样化的 RL 环境数据集，你可以拉下杠杆，使用你喜欢的微调框架，然后拉下杠杆，得到一些相当不错的东西。

我确实认为有一些非常有价值的强化学习环境是人们可以想到的，我认为这些不属于实验室的关注范围。我不想泄露答案，但有一个领域我认为非常宝贵。抱歉，我不是想在舞台上含糊其辞，但确实有一些这样的例子。

另一方面，你认为什么仍然让人觉得只有在远处看才可自动化？

我确实认为，归根结底，几乎所有事情都可以在某种程度上变得可验证——有些事情比其他的更容易。因为即使是写作之类的事情，你可以想象有一个 LLM 评审委员会，并且可能从这种方法中得到合理的结果。所以这更多的是关于什么容易、什么困难。我认为最终一切都是可自动化的。

### Vibe Coding 与代理工程

去年你创造了"vibe coding"这个术语，今天我们处在一个感觉更严肃的世界——更多的"代理工程"。你认为两者之间的区别是什么，你会怎么称呼我们今天所处的阶段？

是的。所以我会说 vibe coding 是关于为每个人提高软件能力的下限。所以下限提高了，每个人都可以 vibe coding 任何事情，这很棒，难以置信。但我会说代理工程是关于保持以前专业软件中存在的质量水准。所以你不能因为 vibe coding 而引入漏洞。你对你的软件仍然负有与以前一样的责任，但你能更快吗？剧透：你能。但如何正确地做到这一点？所以对我来说，代理工程——当我这样称呼它时，因为我确实认为它是一个工程学科——你有这些代理，它们是这些刺状的实体。它们有些容易出错，有些随机性，但它们非常强大。你如何协调它们来更快地前进，同时不牺牲你的质量水准？正确而良好地做到这一点，就是代理工程的领域。

所以我认为它们是不同的——一个是关于提高下限，另一个是关于延伸上限。我所看到的是，代理工程能力的天花板非常高。人们过去谈论 10 倍工程师——我认为这个倍数被放大了很多。10 倍并不是你获得的加速。从我目前的视角来看，那些非常擅长这个的人似乎远不止 10 倍。

### AI 原生编程的样子

Sam Altman 去年在 AI Engineer 大会上说过一句令人难忘的话——不同代的人使用 ChatGPT 的方式不同。所以如果你在 30 多岁，你把它当作 Google 搜索的替代品。但如果你在十几岁，ChatGPT 是你通往互联网的门户。今天编程中的平行对应是什么？如果我们观察两个人使用 OpenClaw、Claude Code、Codex 编程——你会认为其中一个很平庸，另一个完全是 AI 原生的——你会怎么描述这种区别？

我认为这就是要充分利用可用的工具——利用它们的所有功能，投入你自己的设置。所以就像以前所有的工程师都基本上充分利用他们使用的工具——无论是 Vim 还是 VS Code，现在又是 Claude Code 或 Codex——投入你的设置，利用你可用的许多工具。我认为看起来就是这样。

一个相关的想法——很多人可能现在正在为此招聘，因为他们想聘请强大的代理工程师。我确实认为大多数人仍然没有重构他们的招聘流程以适应代理工程能力。如果你在出谜题来解决，这仍然是旧的范式。我认为招聘必须看起来像这样：给我一个真正大的项目，看那个人实现这个大项目。比如让我们为代理写一个 Twitter 克隆，然后让它非常好、非常安全，然后让一些代理在这个 Twitter 上模拟一些活动，然后我用 10 个 Codex 5.4x 以 X 高位尝试攻破你部署的网站，它们尝试攻破它，它们不应该能攻破。所以也许看起来就是这样。在这种环境中观察人们——构建更大的项目，利用工具——可能就是我主要关注的方式。

### 品味、判断力与人在回路中的作用

随着代理做得越来越多，你认为人类的什么技能变得更加有价值，而不是更少？

目前的答案是，代理有点像这些实习生实体。所以值得注意的是——你基本上仍然要负责审美、判断力、品味，以及一定的监督。

我最喜欢的关于代理奇怪之处的例子是——对于 MenuGen，你用谷歌账户注册，但通过 Stripe 账户购买积分，两者都有电子邮件地址。我的代理在购买积分时，实际上尝试用 Stripe 的电子邮件地址关联到谷歌电子邮件地址——就像没有一个持久的用户 ID。对人来说，它试图匹配电子邮件地址，但你可以为你的 Stripe 和谷歌使用不同的电子邮件地址，那么资金就无法关联。这就是这些代理仍然会犯的错误——为什么你会用电子邮件地址来交叉关联资金？它们可以是任意的。你可以用不同的电子邮件。做这样的事情太奇怪了。

所以我认为人们必须负责这个规格说明、这个计划。而且我实际上甚至不太喜欢计划模式。显然它非常有用，但我认为这里有更普遍的东西——你必须与你的代理一起设计一个非常详细的规格说明——也许基本上就是文档——然后让代理来写它们，你负责监督和顶层分类，但代理在做很多幕后工作。所以你不关心某些细节。

另一个例子是神经网络中的数组或张量。PyTorch 和 NumPy 以及所有不同的——Pandas 等等——所有不同的 API 细节之间的区别太多了。而且我已经忘记了 keep_dims 和 keep_dim 之间的区别，或者它是 `dim` 还是 `axis`，或者 reshape 还是 permute 还是 transpose。我不再记得这些东西了。因为你不需要。这是由实习生处理的细节类型，因为他们有非常好的记忆力。但你仍然需要知道，例如，有一个底层张量，一个底层视图，然后你可以操作同一存储的视图，或者你可以有不同的存储，这就不那么高效了。所以你仍然需要理解这些东西在做什么以及一些基础知识，这样你就不会不必要地复制内存等等。但 API 的细节现在被移交了。所以你负责品味、工程、设计——以及确保它有意义，确保你要求的是正确的事情。比如，好的，这些必须是唯一的用户 ID，我们将所有东西关联到它。所以你做一些设计和开发，而工程师做填空。这就是我们目前所处的阶段。

你认为这种品味和判断力会随着时间推移变得越来越不重要吗，还是天花板只会不断升高？

我希望它会改善。我认为它现在没有改善的原因可能又是——它不是 RL 的一部分。可能没有审美成本或奖励，或者它不够好之类的原因。我确实认为，当你实际查看代码时，有时我有点心脏病发作，因为它并不总是超级棒的代码。而且它非常臃肿，有大量的复制粘贴，有脆弱的尴尬抽象，它能工作但实在很糟糕。我确实希望这能在未来的模型中得到改善。

另一个很好的例子是 microGPT 项目，我试图将 LLM 训练简化到尽可能简单。模型讨厌这样。它们做不到。我不断提示 LLM 简化、再简化，它就是做不到。你感觉你处于 RL 回路之外。感觉就像拔牙。它不是光速。所以我确实认为人们仍然负责这个。但没有什么根本性的东西阻止它。只是实验室还没有做，差不多就是这样。

### 动物与鬼魂：理解 LLM 的本质

所以我很想回到这个"锯齿状智能"的想法。你写了一篇发人深省的文章，关于"动物与鬼魂"。这个想法是，我们不是在构建动物，我们是在召唤鬼魂。这些是由数据和奖励函数塑造的锯齿状智能实体，但不是由内在动机、乐趣、好奇心或赋权塑造的——这些是通过进化产生的东西。为什么这个框架很重要，它实际上会如何改变你构建、部署、评估甚至信任它们的方式？

我写这篇文章的原因是，我试图理解这些东西是什么。因为如果你有一个好的模型知道它们是什么或不是什么，你就会更擅长使用它们。我不确定它是否有真正的实际力量。我认为这有点哲学化。但这只是接受这样一个事实：这些东西不是动物智能。比如你对着它们大喊大叫，它们不会工作得更好或更差——这没有任何影响。这都只是统计模拟回路，基底是预训练（所以是统计学），然后 RL 叠加在上面，所以它增加了权重参数。也许这只是一个心态问题——我面对的是什么，什么可能工作或不太可能工作，或者如何修改它。但我实际上没有——这是让你的系统变得更好的五个明显结果。更多的是对它保持怀疑，并随着时间的推移去弄清楚。这是起点。

### 代理原生基础设施

好的，你深入参与了代理的工作——它们不仅仅是聊天——它们有真正的权限，有本地上下文，它们实际上代表你采取行动。当我们都开始生活在那个世界时，会是什么样子？

我认为这里很多人可能对代理原生的代理环境感到兴奋。所有东西都必须重写。所有东西仍然从根本上是为人类编写的，必须被重新设计。我大多数时候使用不同的框架或库时，它们仍然有从根本上为人类编写的文档。这是我最喜欢的痛点。为什么人们还在告诉我该做什么？我什么都不想做。我应该复制粘贴给代理的是什么？每次我被告知"去这个 URL"之类的，我就觉得——啊。

每个人都在兴奋于如何将需要发生的工作负载分解为对世界的传感器、对世界的执行器。我们如何让它成为代理原生的？基本上，首先为代理描述它。然后有很多关于对 LLM 非常易读的数据结构的自动化。

对于 MenuGen，著名的——当我写关于 MenuGen 的博客文章时——很多麻烦甚至不是为 MenuGen 写代码，而是把它部署在 Vercel 上，因为我必须处理所有这些不同的服务，我必须把它们串联起来，我必须去它们的设置和菜单，配置我的 DNS，这太烦人了。所以这是一个很好的例子：我希望 MenuGen 是，我可以给 LLM 一个提示词"构建 MenuGen"，然后我什么也不用碰，它就同样以这种方式部署在互联网上。我认为这将是一个很好的测试，看看我们的基础设施是否变得越来越代理原生。

最终，我认为我们正走向一个世界——有代理代表个人和组织。"我会让我的代理和你的代理沟通"，来解决我们会议之类的一些细节。所以我确实认为这就是大方向。

### 教育：外包思考，而非理解

我想我们得以一个关于教育的问题来结束。因为你可能是世界上最擅长把复杂技术概念变得简单的人之一，并且对如何围绕它设计教育有着深刻的思考。当智能变得廉价，我们进入 AI 的下一个时代时，还有什么仍然值得深入学习？

最近有一条推文让我震惊，我几乎每隔一天就会想起它。大意是：**"你可以外包你的思考，但你不能外包你的理解。"**

我认为这说得非常好。因为我仍然是系统的一部分，我仍然必须——信息仍然必须进入我的大脑——我感觉我正在成为一个瓶颈，甚至只是在知道我们试图构建什么、为什么值得做、如何指导我的代理等等方面。所以我仍然认为，最终必须有人来指导思考和处理，而这在根本上仍然受到理解的限制。

这也是我对所有 LLM 知识库感到非常兴奋的一个原因——因为我觉得这是一种让我处理信息的方式。每当我看到信息的不同投影时，我总觉得获得了洞见。所以对我来说，它真的只是很多提示词，对某些固定数据进行合成数据生成。我非常享受每次阅读文章时——我的 Wiki 正在从这些文章中构建起来，我喜欢对事情提出问题。我认为，最终这些工具是以某种方式增强理解的工具。而这仍然是一个瓶颈，因为如果你不能——因为 LLM 当然不擅长理解，你仍然独特地负责这件事。所以在这方面起作用的工具，我认为是极其有趣和令人兴奋的。

我很高兴几年后能回到这里，看看我们是否完全被自动化出了这个循环，它们是否真的也接管了理解。非常感谢你加入我们，Andrej。我们非常感谢。

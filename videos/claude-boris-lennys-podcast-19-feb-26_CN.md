生成的。很多人甚至不再看代码了——我们能在多大程度上归功于你启动的这个小小项目以及你的团队在过去一年中将其规模化？我很好奇你对你这一年的工作及其影响的感想。这些数字实在太疯狂了，对吧？全世界 4% 的提交，这远远超出了我的想象，而且正如你所说，这还只是起点。这些还只是公开的提交。实际上，如果算上私有仓库，这个比例会高得多。我觉得最疯狂的不是我们现在的数字，而是我们的增长速度，因为如果你看 Claude Code 在任何指标上的增长率，它都在持续加速。它不仅在增长，而且在越来越快地增长。当我刚开始做 Claude Code 的时候，它本来只是一个小 hack。我们在 Anthropic 大致知道我们想发布某种编程产品。长期以来，Anthropic 构建模型的方式符合我们对构建安全 AI 的心智模型：模型先变得非常擅长编程，然后变得非常擅长使用工具，然后变得非常擅长使用电脑——大致就是这个轨迹。我们已经在这方面工作了很长时间。我最初加入的团队叫做 Anthropic Labs 团队，实际上 Mike Krieger 和 Ben Mann 最近又为第二期重新启动了这支团队。这个团队构建了一些很酷的东西：我们构建了 Claude Code、MCP、桌面应用。你可以看到这个想法的种子——先是编程，然后是工具使用，然后是电脑使用。这对 Anthropic 之所以重要，是因为安全——又回到了这一点。AI 正变得越来越强大，越来越有能力。过去一年发生的事情是，至少对工程师来说，AI 不仅仅写代码，它不只是对话伙伴，它还能使用工具，它在世界中行动。现在随着 Co-Work 的推出，我们开始看到非技术人员也在经历这种转变。对很多使用对话式 AI 的人来说，这可能是他们第一次使用真正能行动的东西——它可以用你的 Gmail，可以用你的 Slack，可以做所有这些事情，而且做得相当好。而且这只会在未来变得更好。所以对 Anthropic 来说，长期以来一直有一种感觉，我们想构建一些东西，但不清楚具体是什么。我加入 Anthropic 后花了一个月的时间做各种 hack，构建了一堆奇怪的原型，大部分都没有发布，甚至接近发布都谈不上——只是在了解模型能力的边界。然后我又花了一个月做后训练，以了解研究方面的情况。说实话，对我来说，作为一个工程师，要想做出好的工作，你必须要理解你工作层面之下的那个层面。在传统工程工作中，如果你在做产品，你需要理解基础设施、运行时、虚拟机、语言等等。但是在 AI 领域，你确实需要在某种程度上理解模型才能做出好工作。所以我绕了一点点弯路去做那件事，然后回来开始构建最终成为 Claude Code 的东西。它最早的版本——我有一段夏天的录像，因为我录了一个 demo 并发了出去。当时它叫 ClaudeCLI。我展示了它如何使用几个工具。最让我震撼的是，我给了它一个 bash 工具，当我问它"我在听什么音乐"时，它竟然能用那个工具写代码来告诉我答案。这是最疯狂的事情，因为我没有指示模型要用这个工具做这个或做那个。模型得到了这个工具，然后自己想出了如何用它来回答我的问题，而我甚至不确定它能不能回答。"我在听什么音乐？"于是我开始进一步做原型。我在内部发了一个帖子，得到了两个点赞——这就是当时的全部反响。因为内部的人可能觉得，说到编程工具，你会想到 IDE，想到各种非常复杂的环境，没人想到这玩意儿可以是基于终端的——这是一种很奇怪的设计方式。这并非我本意，但最开始我是在终端里构建的，因为在最初的几个月里只有我一个人，这是最简单的构建方式。对我来说，这其实是一个很重要的产品经验：在开始的时候，你想让资源稍微匮乏一点。然后我们开始考虑应该构建哪些其他形式，但我们决定在终端上再坚持一段时间。最大的原因是模型改进得太快了，我们觉得没有任何其他形式因素能够跟得上模型的变化。说实话，这很大程度上是我在挣扎——到底应该构建什么？过去的一年里，Claude Code 就是我所想的一切。深夜时分，这就是我在想的事情：模型在持续改进，我们该怎么办？我们怎样才能跟上？终端真的是我当时唯一想到的方案。结果它在我发布后很快就流行起来了。它在 Anthropic 内部成为了热门，日活用户直线上升。实际上在发布之前，Ben Mann 就催我做 DAU 图表。我当时觉得是不是太早了，他说"不"。结果图表立刻就垂直上升了。然后在 2 月，我们对外发布了。实际上有一件事大家可能不记得了：Claude Code 发布之初并不是一个爆款。它确实获得了一批用户，有很多早期 adopters 立刻理解了它，但真正让所有人都理解这个东西花了好几个月。因为它太与众不同了。我认为 Claude Code 之所以能成功，部分原因是"潜在需求"这个理念——我们把工具带到人们所在的地方，让现有的工作流程变得更轻松一些。同时因为它在一个终端里，有点令人惊讶，有种陌生感，所以你得保持开放的心态，学会使用它。当然现在 Claude Code 已经可以在 iOS 和 Android 的 Claude 应用中使用，在桌面应用中使用，在网站上使用，作为 IDE 扩展使用，在 Slack 和 GitHub 中使用——在工程师所在的各个地方，它变得更熟悉了，但那不是起点。所以在一开始，这个东西竟然有用，这本身就是个惊喜。随着团队成长、产品成长，随着它对世界各地的人们——从小初创公司到最大的 FAANG 公司——变得越来越有用，他们开始使用并给予反馈。回想起来，这是一次非常谦卑的经历，因为我们不断从用户那里学习。最激动人心的是，我们没有人真正知道自己在做什么，我们和其他人一样在摸索，而最好的信号就是来自用户的反馈。我被震惊了太多次。在当今世界，事情变化之快令人难以置信。你一年前推出了这个产品，而它甚至不是人们第一次能用 AI 编程。但就在一年时间里，整个软件工程职业已经发生了翻天覆地的变化。所有的预测都说 AI 将编写 100% 的代码，每个人都说"不，那太疯狂了"，现在呢？

[`13:53`](https://youtu.be/We7BZVKbCVw?t=833) 当然正在发生，正如他们所说。事情变化太快了。

[`13:59`](https://youtu.be/We7BZVKbCVw?t=839) 确实很快。回顾一下，去年五月在 Claude 的 Code 活动上，那是 Anthropic 第一次举办开发者大会。我做了一个简短的演讲，在问答环节人们问我年底的预测是什么。我 2025 年 5 月的预测是：到年底你可能不再需要 IDE 来编程了，我们将开始看到工程师不再做这个了。我记得当时现场一片倒吸冷气的声音。这是一个非常疯狂的预测。但在 Anthropic，我们思考问题的方式就是指数思维，这深深植根于我们的 DNA 中。我们的三位联合创始人是 scaling laws 论文的前三位作者。所以我们确实是用指数思维思考的。如果你看一下当时 Claude Code 编写代码百分比的指数曲线，只要沿着那条线画下去，很明显我们会在年底达到 100%，即使这与直觉完全不符。我所做的就是画那条线。果然，在 11 月，这在我个人身上实现了，并且一直保持到现在。我们也开始在很多不同客户身上看到这一点。我觉得你刚才分享的关于这个过程的很有意思——就是到处玩一玩、看看会发生什么。这在 OpenAI 的故事里也经常出现，就是 Peter 在那里玩，然后事情就发生了。感觉这是 AI 领域许多重大创新的核心要素——人们就是坐在那里尝试东西，把模型推到比大多数人更远的地方。

[`15:23`](https://youtu.be/We7BZVKbCVw?t=923) 这就是创新的本质，你不能强迫它，没有创新的路线图。你只能给人们空间，给他们——或许这个词是"安全感"——心理上的安全感，让他们知道失败是可以的，80% 的想法是糟糕的也没关系。同时你也要让他们承担一定的责任：如果想法不好，就要及时止损，转向下一个想法，而不是继续投入更多。在 Claude Code 的早期，我完全不知道这东西会变得有用。因为甚至在 2 月发布时，它大概只写了我 20% 的代码，不多。到 5 月，大概 30%。我大部分代码仍然在用 Cursor。直到 11 月才跨越了 100%。这花了一段时间。但从最早的日子起，我就感觉我抓到了一些东西。我每个晚上、每个周末都在 hack 这个东西。幸运的是，我的妻子非常支持。但就是感觉我抓到了什么，虽然不明确是什么。有时候你发现一根线，就得拽一拽它。

# 验证检查清单 — README CONCEPTS 章节

验证 CONCEPTS 表格准确性的规则。每条规则在每次工作流运行时都会进行检查。

## 规则

### 1. 外部 URL 可用性
- **类别**：URL 准确性
- **检查内容**：CONCEPTS 表中的每个外部 URL（文档链接）返回有效页面
- **深度**：获取每个 URL 并确认它加载到预期页面（非重定向到错误页面）
- **对比来源**：`https://code.claude.com/docs/llms.txt` 的规范 URL 列表
- **添加日期**：2026-03-02
- **来源**：发现权限 URL `/iam` 重定向到身份验证页面而非权限页面

### 2. 锚点片段有效性
- **类别**：URL 准确性
- **检查内容**：任何带有锚点片段（`#section-name`）的 URL 匹配目标页面上的实际标题
- **深度**：获取页面并验证标题是否存在且具有预期的锚点
- **对比来源**：获取的页面内容
- **添加日期**：2026-03-02
- **来源**：Rules 锚点 `#modular-rules-with-clauderules` 已过时；章节已重命名为 `#organize-rules-with-clauderules`

### 3. 缺失的文档页面
- **类别**：缺失概念
- **检查内容**：官方文档索引（`llms.txt`）中代表面向用户功能的每个页面在 CONCEPTS 表中都有对应的行
- **深度**：将完整文档索引与 CONCEPTS 表条目进行比较
- **对比来源**：`https://code.claude.com/docs/llms.txt`
- **添加日期**：2026-03-02
- **来源**：发现多个缺失概念（代理团队、键绑定、模型配置等）

### 4. 本地徽章链接有效性
- **类别**：徽章准确性
- **检查内容**：CONCEPTS 表中的每个徽章目标路径（`best-practice/*.md`、`implementation/*.md`、`.claude/*/`）指向存在的文件或目录
- **深度**：使用 Read/Glob 验证文件存在性
- **对比来源**：本地文件系统
- **添加日期**：2026-03-02
- **来源**：初始检查清单创建

### 5. 描述时效性
- **类别**：描述准确性
- **检查内容**：每个概念的描述准确反映当前官方文档的描述
- **深度**：将 README 描述与官方页面的元描述或第一段进行比较
- **对比来源**：官方文档页面内容
- **添加日期**：2026-03-02
- **来源**：记忆描述缺少自动记忆；MCP 服务器位置缺少 `.mcp.json`

### 6. TIPS 章节 URL 一致性
- **类别**：URL 准确性
- **检查内容**：当 CONCEPTS 或 Hot 表中的 URL 更新时，同时检查 TIPS 章节中是否存在相同的过时 URL
- **深度**：搜索 TIPS 章节（第 125–267 行）中每个在 CONCEPTS/Hot 表中被标记的 URL
- **对比来源**：llms.txt 站点地图 + CONCEPTS 表 URL
- **添加日期**：2026-04-16
- **来源**：`web-scheduled-tasks` URL 已在 Hot 表中修复（2026-04-14），但相同的过时 URL 仍然存在于 TIPS 中（第 223 行）

### 7. Beta 徽章时效性
- **类别**：徽章准确性
- **检查内容**：Hot 表中标记为 `![beta](!/tags/beta.svg)` 的概念在其官方文档页面中仍应被标记为 beta / 研究预览（标题横幅、"研究预览"文本或环境变量门控）
- **深度**：获取每个上游页面并检查是否有明确的 beta/预览/实验性措辞；如果不存在，则 README 徽章可能已过时
- **对比来源**：官方文档页面横幅文本 + GA 标记文本
- **添加日期**：2026-04-26
- **来源**：workflow-concepts-agent 标记了 Routines、No Flicker Mode、Computer Use 和 Code Review 在 README 中带有 beta 徽章，但它们的文档页面看起来已经是 GA（置信度 0.6）— 这种漂移类型不被现有的描述时效性规则覆盖

### 8. 位置列事实准确性
- **类别**：描述准确性
- **检查内容**：每个概念的**位置**列（第 2 列）值必须在事实上匹配官方文档中描述的机制 — 不仅是路径/命令/标志存在，而且特征的定性描述是正确的（例如特征如何存储状态、它跟踪什么、配置在哪里）
- **深度**：对于任何做出机制性声明的位置值（例如"基于 git"、"自动"、"内置（环境变量）"、"云后端"），获取官方页面并根据文档自身对机制的描述确认该声明
- **对比来源**：官方文档页面正文（机制/"工作原理"章节）
- **添加日期**：2026-05-21
- **来源**：Checkpointing 的位置在每次先前运行中都写为 `automatic (git-based)`，但 `/en/checkpointing` 明确说明检查点跟踪文件编辑工具更改（非 git、非 bash），并且"不能替代版本控制" — *"将检查点视为'本地撤销'，将 Git 视为'永久历史'。"* 现有的规则 #5（描述时效性）仅检查描述列，因此位置列中的事实错误被无限期地未被检查

# 第 1 天 — 与 Claude Code 的第一次对话

[返回第 0 天（安装配置）](../day0/README.md)

---

您已经安装了 Claude Code。接下来呢？本指南将带您了解使用它的三个层级 — 每个层级都让您对 Claude **如何**完成工作拥有更多控制权。

可以把这想象成雇佣人员：
1. **提示** = 在街上向陌生人问路
2. **智能体** = 雇佣一位总是以特定方式做事的专家
3. **技能** = 该专家针对特定任务拥有特定训练

---

## 层级 1：提示（直接提问）

> **可以把它想象成**给一位知识渊博的朋友发短信。你问"卡拉奇天气怎么样？"，他们会给你*一个*答案 — 但你不知道他们是查了天气应用、看了窗外，还是仅凭记忆猜测。

打开终端并输入 `claude`。您现在进入了一个对话界面。尝试输入：

```
what is the weather in Karachi?
```

Claude 会回答 — 但它**如何**回答是不可预测的。它可能会：
- 从训练数据中提取（可能已过时）
- 搜索网络（如果网络工具可用）
- 给出一个通用答案而非实时数据

对于快速问答来说，这完全没问题！但如果您需要**一致、可靠的结果**，仅靠提示是不够的。

### 提示在哪些场景下效果很好

- 询问代码库相关问题（"这个文件是做什么的？"）
- 撰写或编辑文档（"把这封邮件改写得更专业一些"）
- 头脑风暴创意（"给我 5 个这个活动的主题行"）
- 解释说明（"用非开发人员也能听懂的方式解释这个错误信息"）

### 局限性

每次您问"天气怎么样？"时，Claude 可能以不同的方式获取数据 — 或者根本不获取真实数据。无法保证它两次使用相同的来源或方法。

## 层级 2：智能体（专家）

**智能体**是扮演特定角色的 Claude — 就像分配一个职位头衔。

> **可以把它想象成**一个餐厅厨房。没有智能体时，你走进一个陌生的厨房大喊"给我做意大利面！" — 听到的人可能煮方便面，也可能做一顿五道菜的意大利盛宴。有了智能体，你雇佣了一位**意面主厨**，其岗位描述写着：*"始终使用新鲜食材，始终煮到弹牙，始终以相同方式装盘。"* 现在你确切知道每次会得到什么。

同样的理念应用到 Claude 上：

> **没有智能体：** 你问 Claude "迪拜天气怎么样？"
> 它可能检查训练数据、搜索网络或进行最佳猜测。你不知道它会做什么。
>
> **有智能体：** 一个 `weather-agent` 有清晰的岗位描述：
> *"始终查询 Open-Meteo API 获取迪拜天气。始终以特定格式返回温度。"*
> 同样的问题，同样的方法，每次都一样。

### 本仓库中的实际示例

本仓库有一个 `weather-agent` — 它的全部工作就是获取迪拜的温度。以下是它和直接提示的区别：

| | 提示 | 智能体 |
|---|---|---|
| **数据来源** | 可能来自任何地方 | 始终来自 Open-Meteo API |
| **地点** | Claude 随意选择 | 始终是迪拜（纬度：25.2，经度：55.3） |
| **格式** | 随机的段落 | 清晰的温度 + 单位 |
| **一致性** | 每次不同 | 每次相同的方法 |

### 要点

智能体为您提供**可预测性**。相同的问题 → 相同的方法 → 相同的质量。这就是优势所在 — 不是智能体更聪明，而是它们**始终如一**。

## 层级 3：技能（专项训练）

**技能**是智能体（或 Claude 本身）可以使用的特定能力。

> **可以把它想象成**新员工的培训手册。当有人加入您的团队时，他们有一个角色（智能体），但还需要完成特定的培训模块 — 如何使用 CRM、如何撰写方案、如何主持站会。每个培训模块就是一个**技能**。角色告诉他们*是什么*；技能告诉他们*如何做*具体的事情。

现在想想一个真实的人：

> **Shayan** 拥有多种技能：
> - 工程技能 — 可以编写代码
> - 游戏技能 — 了解游戏机制
> - 阅读技能 — 能够消化和总结长文档
>
> 每种技能都有自己的知识和方法。Shayan 为合适的任务使用合适的技能。

Claude 的工作方式相同。`weather-agent` 有一个名为 `weather-fetcher` 的技能：

- **智能体**（`weather-agent`）= 职位头衔为"天气播报员"的人
- **技能**（`weather-fetcher`）= 关于*如何*获取天气数据的专项训练

技能包含精确的指令：
1. 调用这个特定的 API URL
2. 从响应中的这个特定字段提取温度
3. 以这个特定格式返回

### 为什么要把智能体和技能分开？

因为**一个智能体可以拥有多种技能**，并且**一种技能可以被多个智能体使用**。

例如，假设您创建了：
- 一个 `daily-report-agent`，用于总结您的一天
- 它可以同时使用 `weather-fetcher` 技能（获取天气）+ `calendar-reader` 技能（查看会议）+ `email-summarizer` 技能（汇总邮件要点）

技能是可重用的构建块。智能体是使用它们的人。

## 融会贯通

以下是完整的架构：

```
层级 1：提示
您 → "天气怎么样？" → Claude 自行想办法回答
                          （方法不可预测）

层级 2：智能体
您 → 天气智能体 → 始终使用相同的方法
                   （方法可预测）

层级 3：技能
您 → 天气智能体 → 使用 weather-fetcher 技能
                   （方法可预测，且有精确指令）
```

每个层级增加更多控制：

| 层级 | 您能控制什么 | 最适合 |
|------|-------------|--------|
| **提示** | 问题 | 快速的一次性问题 |
| **智能体** | 问题 + 谁来回答 | 可重复的任务 |
| **技能** | 问题 + 谁来回答 + 如何完成 | 关键工作流程 |

## 2. 新版 LEVELS 映射（键名和颜色不变）

新版章节顺序为：**代理 → 技能 → 上下文 → CLAUDE.md → 命令**。`workflow` 层级键从 `data-level` 使用中移除（章节分隔符失去 `data-level`）。`LEVELS` 映射仍保留 `workflow` 用于导航栏历史显示，但无幻灯片触发它。

**修订方案**：从 LEVELS 映射中完全移除 `workflow` 层级，因为没有幻灯片携带 `data-level="workflow"`。导航栏最高到 `commands`（83%）。这没问题——工作流章节作为命令章节*内部*的高潮部分呈现，而非独立主题。

实际上，导航栏仅填充到 83% 而非 100% 就进入结束章节，这令人不够满意。更好的方案：**将命令+工作流合并为一个名为"命令与工作流"的章节**，使用 `data-level="commands"`。在 LEVELS 中保留 `workflow` 层级为 100%，并将 `data-level="workflow"` 分配给*原*工作流章节分隔符幻灯片——它在命令章节内部成为一个视觉过渡。这样导航栏在工作流幻灯片处就能填满到 100%。

**最终决定**：在 LEVELS 中同时保留 `commands`（83%）和 `workflow`（100%）。将 `data-level="commands"` 分配给命令章节分隔符，将 `data-level="workflow"` 分配给工作流子章节幻灯片。导航刻度保持不变。这与当前结构完全一致——只是内容幻灯片重新排序。

## 6. 实施方案

HTML 是一个大文件。当前幻灯片顺序不符合新叙事脉络。最简洁的实施方式如下：

1. 剪切幻灯片 div 并按新顺序粘贴（7-12 = 原 18-23，13-18 = 原 24-29，19-23 = 原 7-11，24-29 = 原 12-17，30-37 不变）。
2. 对所有 `data-slide` 属性按顺序重新编号。
3. 更新章节幻灯片的 `data-level` 属性。
4. 更新章节分隔符上的章节编号文字和 h1 标题。
5. 更新幻灯片 6 上目录的 `goToSlide` 目标。
6. 更新工作流章节幻灯片（原 33）的章节编号文字。
7. 按需对天气报告器框架进行有针对性的内容编辑。
